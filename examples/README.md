# 完整示范：一次计分 Bug 的沟通与纠偏

对应 [01 任务交代](../lessons/01.md)、[06 调试](../lessons/06.md)、[11 效率](../lessons/11.md)。先做练习，再看示范。沿用第06课的缺陷，不另建新游戏和另一套调试方法。

这是可运行的教学重演，过程为作者编排；不是一段真实用户聊天历史，也不是 Codex 必然采取的行为。代码与检查可以在本仓库实际执行。

## 1. 原始请求

> 分数不对，帮我修一下。

不足：缺少输入、正确结果和“保留输入顺序”的约束。示范不先铺设框架或重写游戏。

## 2. 可执行任务

> 修复 labs/bugs/buggy_score.py 的 positive_score。输入 [3,-2,5] 应得到 8，函数不能改变传入列表。只处理正分统计，覆盖空列表、全负数、零和混合输入；报告实际检查。先定位函数，不修改其他玩法。

这是示范范围的代码修复请求；教学时学习者需要自己写指令，不能把它当独立完成。

## 3. 定位与验收

原实现排序输入并把负数也相加。两个独立问题：结果为 6，且顺序改变。先把“正确得分”和“输入保持不变”分别列为验收；一个成功不能替代另一个。

## 4. 不完整修复与精确反馈

教学中的不完整修复只过滤负数，仍保留排序。得分变成 8，但副作用仍在。

> 混合输入的得分已正确，但调用后原列表由 [3,-2,5] 变为 [-2,3,5]。请保留当前正分规则，消除输入变更，并验证结果和输入两项；不扩展到其他计分功能。

反馈保留已正确行为，同时给出可复现差异，无需说“整个都不对，重做”。

## 5. 最小修复与真实检查

参考实现见 score_fix.py。运行：

```bash
python3 examples/score_walkthrough.py
```

实际应看到：原始得分 6/输入保留 False；不完整修复 8/False；参考修复 8/True；四组检查通过。脚本打印的“通过”只针对这里的函数，不代表整个游戏已玩测。

## 6. 交付与成本复盘

交付说明只需：改了正分过滤及副作用，列出实测检查，注明没有运行整个游戏。记录耗时与纠偏次数；本示范没有真实模型 token 对照，不宣称节省比例。

## 7. 独立迁移

换成“只累加大于指定阈值的得分，保留输入”，自己写提示与边界用例。导师检查你能否解释阈值相等时的规则。完成变体才用于判断掌握，示范重放不算独立通过。
