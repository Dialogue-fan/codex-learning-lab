# 21 · 游戏存档与版本兼容

交付专题 · 90 分钟，可拆分。前置：[状态调试](06.md)、[版本管理](07.md)。

## 学习目标与范围

保存玩家长期进度，在数据格式变化时保护旧数据。06 课负责通用复现和验证，07 课负责源码恢复；本课专门处理玩家数据，不重讲 Git 操作。

## 先答后看

哪些游戏状态应该保存：最高分、当前按键、窗口句柄、关卡进度、冷却计时？逐个解释；哪些需要恢复设计，哪些可以清零？导师等你回答后再给建议。

## 核心设计

存档只包含明确的数据字段，不直接序列化运行时对象。先定义字段类型、范围、schemaVersion、默认值与不支持版本的处理。源码版本与存档格式版本不同。迁移必须保留原数据，可重复执行，并验证新数据；损坏时不能用默认值悄悄覆盖唯一副本。

浏览器练习可用 localStorage；明确它与来源地址绑定、用户可能清除它，不能当作可靠云备份。文件存档路线应考虑临时写入、备份和替换失败；按目标平台验证，不假定所有存储都有相同写入行为。

## 互动任务

1. 在独立游戏变体加入最高分保存，写清字段与验收，不保存实时按键等对象。
2. 建 v1 样本 `{schemaVersion:1,bestScore:10}`，再设计 v2，例如增加已解锁关卡列表；先定义缺失字段的迁移规则。
3. 指挥 Codex 分开实现读取、校验、迁移、写入；先拿样本验证，再接游戏。让导师检查是否在校验前写入了原数据。
4. 用正常 v1、正常 v2、缺字段、负数、截断 JSON、未来版本六类样本测试。未来版本明确拒绝或按规格降级，不默默猜测。
5. 模拟持久化不可写：让写入接口抛错。确认游戏可报告失败、仍能继续进行，旧数据没有丢失。重新打开后检查最高分；保留恢复说明。

## 沟通示例

> 给本项目加入最高分存档。先确认字段、存储位置及 v1→v2 兼容方案。保留原数据，校验后再写；损坏或未来版本要明确报告。验证首次启动、正常读写、旧版迁移、损坏和写入失败。交付迁移样本、检查结果与恢复方式。

## 提交与验收

提交 workbook/21-save.md、自己的实现和样本。使用 [存档检查模板](../templates/save-release.md)。

- 新会话/重新打开能读到有效进度，临时状态按规格重置。
- v1→v2 结果正确；重复迁移不继续改变数据。
- 六类样本均有预期与实际；写入失败不破坏已有数据。
- 能解释存档位置、版本和恢复步骤；不可访问的设备不声称已验证。

沿用 [统一评分](../docs/assessment.md)，未满足具体条件先补练。

## 三级提示与迁移

一级：读取失败与数据无效是同一个问题吗？二级：将解析、验证、迁移、持久化分成能单独测试的函数。三级：导师示范一个旧版字段补默认值，你独立完成损坏与未来版本的处理。迁移到背包存档时先定义物品标识和已删除物品的处理，不复制此例的最高分结构。
